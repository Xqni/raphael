# Adversarial Design Review — Raphael System (2026-10-09)

**Reviewer stance:** skeptical senior systems architect, explain-or-reconcile rule.
**Scope (reading budget):** supervisor relay/bring-up + wsl-relay.py · ws.py/app.py auth+foreground gate · jobs engine + input lock · router chain/admission · audio_in VAD/grace · conductor bus · persona tiers · confirm layering + Core Guard. Live stack RUNNING — nothing touched.
**Method:** targeted greps + windowed reads with file:line evidence; full-file reads only for `scripts/wsl-relay.py` (190 lines).

## Verdict

The architecture is **sound and unusually self-documenting**: the audited decisions (relay topology, loopback bind contract, fail-closed privacy gates, confirm timeout-abort, conductor lock discipline) each carry an inline *why* with dates and incident references, which is exactly what this review's rule demands — most findings below reconcile cleanly. There is **no CRITICAL hole**: the security invariants hold (loopback-only binds end-to-end, constant-time token auth with rate-limited failures, role capability tables, Core Guard hash-pinning of safety files), and the safety confirmation path is genuinely enforced (timeout aborts, never auto-approves; voice "yes" rejected for HIGH risk). The real defects cluster in three places: (1) the **Wave 5P `safety.confirm_policy` map is dead configuration** — no Python file reads it, and its documented `default: confirm` is contradicted by code that defaults to *allow* for anything the regex deny-list misses; (2) a **legacy-incident asymmetry** — the 2026-10-08 zombie-listener fix was applied to the Windows relay leg but not to the WSL helper leg, which has no watchdog to recover; (3) **worker-pool head-of-line blocking** — an input-lock wait consumes one of 8 job workers, so a GUI burst starves chat/analysis. Everything else reviewed is either explained-with-evidence or a LOW polish note. Recommendation: fix the two HIGH confirm-layer findings before any further autonomy expansion (they are config/doc-trust hazards, not live exploits), port one 10-line guard to `wsl-relay.py`, and the system is in good shape for Wave 6.

## Top-10 reconsideration list

1. **Wire or delete `safety.confirm_policy`** (config.yaml:116-139) — dead safety config is worse than no config; it manufactures false confidence in exactly the layer that must not have any (finding 1).
2. **Reconcile `default: confirm` vs `classify()` default-allow** (config.yaml:120 vs confirm.py:141-142) — the documented and the actual safety default must be the same sentence (finding 2).
3. **Port the zombie-listener guard to `wsl-relay.py` accept loop** (wsl-relay.py:178-179) — the incident already proved this failure class; the helper is the one leg left unguarded and unwatched (finding 3).
4. **Move input-lock acquisition out of the worker slot** (loop.py:599 / engine.py:286) — one GUI burst currently starves every chat and analysis job; cheapest structural fix in the review (finding 4).
5. **Make the foreground fail-closed refusal legible** (router/core.py:398-411) — keep failing closed, but tell the user *why* via the existing notice path instead of a generic E_OFFLINE (finding 5).
6. **De-duplicate model policy** (MODEL_POLICY.md vs ~/AGENTS.md) — two current-looking tier tables is a money-burn vector; single-source it (finding 6).
7. **Split supervisor/main.py** into relay + wsl bring-up modules (finding 7) — pure moves, test-backed, restores reviewability before Wave 6 grows it further.
8. **Watchdog the conductor itself** (conductor tmux = sole bus-delivery dependency, PROGRESS.md:131) — the STOP file kills launches by design; an *accidental* conductor death must not silently mute a 10-lane pipeline (finding 8).
9. **Pre-filter the router chain by capability** (core.py:614, groq caps={'stt'}) — make "STT-only tail" structurally true rather than relying on a failed pick (finding 9).
10. **Self-check the helper's bind address** (wsl-relay.py:138-149) — only after #3's watchdog exists, so an exit can actually be recovered (finding 12).

## What is RIGHT

- **Relay topology is justified, not improvised.** The 3-hop chain (win 127.0.0.1 → VM NAT IP → brain loopback) exists because the Hyper-V firewall verifiably blocks native WSL localhost forwarding; the narrow-rule (`allow-brain-localhost.ps1`) and mirrored-networking end-states are documented as the relay-free targets, and mirrored mode auto-skips the relay (main.py:1483-1495). Bind audits are dated and explicit: Windows leg hardcoded `127.0.0.1` "NOT configurable" (main.py:1432-1445); the helper refuses wildcard and exits 1 without a NAT address (wsl-relay.py:159-171). This is how you explain a workaround.
- **Dead-peer handling is layered, not single-mechanism:** SEC-6 TCP keepalive (~30s+3×1s probes) *plus* a select-based 90s idle cap ≥3× the 10s WS ping in both legs, with the "connect timeout must NOT persist as recv timeout" trap documented at both call sites (main.py:1533-1536, wsl-relay.py:112-117). The 2026-10-08 zombie-listener root-cause fix (main.py:1575-1590) keeps the bounded splice semaphore and only exits on a genuinely dead socket.
- **WS auth is textbook:** constant-time `hmac.compare_digest`, upgrade-time token check as defense-in-depth, 5s auth deadline, ≥5 fails/60s → 5min per-IP ban, role capability tables enforced server-side (`CAN_SEND_*`, ws.py:41-51), 8 MiB msg cap, per-connection rate limits with binary audio exemption, session bound before registration, disconnect cancels that session's jobs (ws.py:224-230).
- **Foreground/privacy gate fails closed by design** with the pre-audit fail-open behavior explicitly named as the thing it replaced (privacy.py:78-94), harness-only pytest escape, secret redaction of every outbound string, no image logging, Private Mode disabling all egress (router/core.py:8-18).
- **Router admission is a real admission controller:** circuit breaker → cooldown → key presence → config gates → RPM → TPM, each with a PROTOCOL §10 error code, Retry-After + rate-limit header honoring, jittered backoff, permanent model-incapability learning that avoids breaker pollution (core.py:428-450, provider.py:57-60), and paid-slot serialization to prevent races on budget gates.
- **Job engine reliability contract is strong:** terminal states immutable, crash recovery marks jobs `interrupted` and *never* auto-resumes them (engine.py:14-16,73-82), per-job tasks with no-orphan cancellation on both job- and worker-shutdown paths (engine.py:280-301), guarded SQL transitions resolving cancel races, and the InputLock's anti-starvation promotion of the oldest live waiter (lock.py:37-57).
- **Confirmation hardening anticipates real attack surface:** voice "yes" rejected for HIGH risk because open-mic speech can be injected by room audio — while voice "no" always works because denying is always safe; timeout aborts, never auto-approves; free-text ambiguity resolves to abort (confirm.py:1-28, 201-211).
- **Core Guard + scanners:** the safety-critical surface (supervisor/**, confirm.py, auth.py, workflows, token-gen, setup scripts) is SHA-256-pinned in `tests/core_guard_manifest.json` and enforced by `tests/core_guard.py` + `tests/security/test_core_guard_and_secrets.py` — tamper-evident with gitleaks baselining and conscious FP retraction records (PROGRESS.md:115,121).
- **Conductor safety model:** flock discipline documented with the per-open-file-description nesting trap, cursors split into a single-writer `cursors.json` to kill a real lost-update race (coord.py:77-103), STOP kill switch, runs-per-hour cap, exponential backoff on 429s, concurrency cap with priority ordering, "NEVER kills interactive sessions; only reaps children it spawned" (conductor.py:19-21).
- **Voice/audio input:** SEC-9 removes runtime pip installs (hash-pinned manifests, loud import failure); AUD-24 bounds the callback→asyncio handoff with drop-oldest stats; the Cut A live bug (WakeStream grace AttributeError killing the wake task at startup) was root-caused and fixed to a single source of truth (`CONTINUATION_GRACE = VadSegmenter.CONTINUATION_GRACE`, audio_in.py:317-320); the TTS echo guard degrades to "no guard, never a dead mic task" (audio_in.py:426-437).
- **config.yaml is a model of config hygiene:** every user decision carries a date and attribution, profiles deep-merge with paid gates kept on regardless of base, no secrets, orb shape_map holds a documented user pin instead of silently diverging, and the persona block binds to a canon-hygienic brief with a *binding debunked-claims register* and a lint test forbidding refuted strings — unusual discipline for a persona layer.
